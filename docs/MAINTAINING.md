# Maintaining the catalog

## How a listing reaches users

1. A contributor opens a pull request adding or changing `plugins/<id>.json`
   and the regenerated `index.json`.
2. The **Validate catalog** workflow runs: the validator's tests, the entry
   rules, `index.json` regenerated and compared, and every package the change
   lists downloaded and compared with its entry (SHA-256, size, the id and
   version inside `plugin.json`). It reads the ZIP in memory and never
   extracts or runs it. It runs with a read-only token, and a fork's pull
   request receives no secrets.
3. A maintainer reviews the pull request. **Passing the checks does not merge
   anything.**
4. The maintainer merges. `main` is what EigenMol reads, so the listing is
   live once GitHub's raw file host refreshes (a few minutes).

`main` is protected: changes arrive through pull requests, the workflow has to
pass, and a code owner's approval is required. Branch protection does not
apply to repository administrators (`enforce_admins` is off), so the owner can
fix the catalog directly in an emergency; the workflow still runs on every
push to `main`, and weekly.

## What the reviewer looks at

The automatic checks cannot judge these:

- **Is it what it says?** The `summary` and `description` describe what the
  plugin computes and do not claim more than it does. A docking score is not
  presented as an affinity; an estimate is not presented as a measurement.
- **Is the network declaration true?** Read the plugin's source for network
  calls in its run path. A plugin that sends a user's structures or results
  anywhere has to say so in `network.note`.
- **Is the source readable?** `source_repository` leads to the code that is in
  the package, or the description says why it does not.
- **Is the publisher entitled to list it?** The contributor publishes the
  plugin or has the publisher's permission; the `license` is stated.
- **Does the id belong to the publisher?** An id in someone else's namespace
  (`org.aigenmol.*`, another organisation's domain) is not accepted from a
  third party.
- **Is the category right**, and is the entry free of tracking links?

Ask for changes in the pull request. Decline a listing that cannot be fixed.

## Ongoing care

- The weekly run downloads every listed package. A failure means a package
  disappeared or changed: open an issue with the publisher, and remove the
  version (or the listing) if it is not fixed.
- Respond to listing-problem issues; remove a dangerous listing first and
  discuss afterwards.
- `index.json` is regenerated by `python3 tools/catalog.py build` and is never
  edited by hand.

## Changing the format

EigenMol reads `schema_version` 1 and ignores fields it does not know. Adding
an optional field is compatible. Anything else — a new required field, a
changed meaning — is `schema_version` 2, and an EigenMol that reads only 1
refuses the whole document with a sentence saying a newer EigenMol is needed.
Change the format only together with an EigenMol release that reads it, and
keep serving schema 1 until those users have moved.
